# 앱 전체 동기화·작업 추적 공통 기준

기준일: 2026-10-15. 사용자 합의된 목표 기준이며, 앱 전체 구현 완료 선언이 아니다.
시코드의 기능 추가·수정·진단과 중앙 기록 연결 작업은 이 문서를 따른다.

## 반드시 지킬 원칙

같은 매장의 권한 있는 휴대폰·중앙·에이전트가 같은 업무 상태와 작업 이력을
확인할 수 있어야 한다. 한 폰에만 남은 실패를 다른 폰에서 정상으로 보이면 안 된다.
**자료·작업 상태의 동기화는 명령 재실행이 아니다.** 다른 폰에서 받은 작업을
실행 큐로 복사하거나 저울 쓰기·라벨 출력을 다시 실행하지 않는다.

오프라인 중 즉시 동일한 상태는 보장할 수 없다. 저장·전달·수신 상태를 명시하고
재연결 후 같은 사건을 빠짐없이 전달하여 공용 상태로 수렴시킨다.
성공만 수집하지 않는다. 실패·취소·대기·결과 미확인도 원본 그대로 보존한다.

## 적용 범위

- 상품·재료·레시피·가격·매장 업무 설정·라벨 템플릿·품질표.
- 생산·저울 누계·보정·포함/제외·할인·폐기·출력 기록과 매출 조회/동기화 상태.
- 저울 상품/성분/광고문구, 장비 연결·읽기·변경·재확인, 업로드·다운로드.
- 위 업무의 조회·저장·삭제·출력·연결·수동 새로고침·취소 등 사용자 의도와 결과.
  화면 이동이나 단순 조회도 조사할 수 있게 기능별 기록 대상을 목록화한다.
  글자 입력마다 원문을 보내거나 모든 터치·스크롤을 녹화한다는 뜻은 아니다.
- 자동 작업은 사용자 조작과 구별하여 시작 원인·부모 작업 ID를 연결한다.

공유는 권한 범위 안에서 한다. 모든 폰에 모든 매장 자료를 무조건 배포하지 않는다.
키·비밀번호·인증 토큰·개인정보·원시 오류는 공유 이력에 넣지 않는다.
프린터 페어링·단말 캐시·화면 크기 같은 기기별 값과 오프라인 임시 편집은
공용 업무 설정과 구분한다. 공유 제외는 기능 목록에 이유를 명시하고 숨기지 않는다.

## 자료·실행·표시의 구분

| 구분 | 기준 |
| --- | --- |
| 업무 원본 | 기존 담당 저장소가 기준. 앱 상품·실제 저울값·실매출을 같은 값으로 덮지 않음 |
| 사용자 작업 | 실행 전 폰에 작업 ID·의도·대상·기준 버전을 내구성 저장 |
| 실행 명령 | 원래 실행 주체만 처리. 공유 받은 폰·조회 에이전트는 실행하지 않음 |
| 작업 사건 | 단계별 사건 ID로 추가 저장, 동일 작업 ID로 연결. 원본 사건 덮기 금지 |
| 공용 현재 상태 | 검증된 사건에서 만든 조회용 투영. 다른 폰·중앙이 같은 기준으로 표시 |
| 단말 대기분 | 공용 목록과 구분 표시. 서버에 보냈다고 거짓 표시하지 않음 |

기존 operation_diagnostics/scale_shared_work/생산 원본/CASPi 영수증/공통 이력을
우선 재사용한다. 새 테이블·RPC가 필요하면 담당·권한·멱등성·버전·전환 시험을
별도 설계하고 적용한다. 이 문서만으로 기존 원본을 옮기거나 SQL을 배포하지 않는다.

## 공통 기록 계약

기존 [운영 기록 계약](OPERATION_HISTORY_GUIDE.md#사건-계약)을 따른다.
기능·매장·대상·작업 ID·사건 ID·시작 주체(사용자/자동)·단말 식별·단계를 연결한다.
사용자 식별은 인증된 범위에서만 사용하고 표시 이름을 인증 증거로 삼지 않는다.
변경 요청/기준값/검증된 실제값/원본 버전을 구별하고 허용된 업무 필드만 기록한다.

발생·폰 저장·서버 수신·마지막 검증 시각을 구별한다. 폰 시계만으로 최신값을
결정하지 않는다. 연결된 서버 버전/순서와 원본 검증을 사용한다.
단계별 안전한 오류 코드와 성공 증거를 남겨 '요청 거절' 하나로 원인을 뭉개지 않는다.
원본이 없는 과거 동작은 추정해서 이력을 만들어 채우지 않는다.

사용자 의도 → 로컬 저장 → 전송/접수 → 실행 → 결과 검증 → 공용 반영을 추적한다.
모든 기능이 모든 단계를 가지는 것은 아니다. 조회·취소·실행 전 실패도 해당 단계와
결과를 남긴다. 취소 기록만으로 이미 전송된 명령의 실제 실행 취소를 단정하지 않는다.

## 동기화·오프라인·충돌

1. 요청·사건은 폰에 먼저 저장한다. 서버 실패로 기록을 버리지 않는다.
2. 서버는 같은 사건 ID의 동일 내용을 중복 저장하지 않는다. 다른 내용이면 충돌로 보존한다.
3. 저장 ACK를 확인한 뒤 전달 커서를 전진한다. 재연결은 전송 재시도이지 명령 재실행이 아니다.
4. 서버 알림/변경분/커서로 다른 폰을 갱신한다. 시작·복귀·재연결 때 누락을 대조한다.
5. 공용 상태와 미전송 로컬 작업을 같은 작업 ID로 합친다. 늦게 온 오래된 사건으로
   완료 상태를 대기로 되돌리지 않는다. 사건 수신과 실행 상태 변경은 별개다.
6. 같은 기준 버전을 서로 다르게 수정했다면 조용히 마지막 값으로 덮지 않는다.
   각 수정·기준 버전·충돌을 보존하고 해당 업무의 병합/사용자 선택 규칙을 적용한다.
7. 결과 미확정 쓰기는 원래 ID로 확인한다. 새 ID·다른 경로로 자동 재쓰기하지 않는다.
8. 오류는 해당 작업/대상/전달 건에만 격리한다. 다른 상품·매장·기능은 계속 처리한다.

수파 초단위 전체 조회·같은 내용 반복 쓰기를 추가하지 않는다. 변경 시 기록,
묶음 전송·중복 억제·변경분 수신을 기본으로 하고 수동 최신 조회는 실제 최신 확인에 쓴다.
정확한 재시도·보관기간·용량 정책은 기존 지침을 따르며 새 기준이 필요하면 별도 합의한다.

## 표시·조회·알림

- 앱은 공용 상태와 이 폰의 미전송분, 동기화 대기/실패, 마지막 확인 시각을 구분한다.
- 접수·실제 적용/재읽기·서버 반영을 모두 '완료'로 묶지 않는다.
- 에이전트는 매장·시간·기능·대상·작업 ID로 같은 사건과 원본 증거를 조회한다.
  관측되지 않는 폰·오래된 기록·기록 공백을 표시하며 기록 없음=정상이라고 하지 않는다.
- 모든 기록을 Telegram으로 발송하지 않는다. 기존 업무 실패/미확정 알림 정책과
  내부 건강 알림 발신 제외를 유지한다. 기록 완전성과 알림 빈도는 별개다.
- 조회 도구가 아직 없는 기능은 미구현으로 표시한다. 없는 API를 만들어 안내하지 않는다.

## 담당과 구현 순서

- 워터비: 공통 기준·기능별 적용 목록·교차 원본 조회·완료 판정.
- 시코드: 공통 기록기/로컬 내구성·공용 동기화/권한·화면 및 기능별 계측.
- 카스씨엘/CASPi: 저울 실행·영수증·ACK/재읽기 원본. CASPi는 수파에 직접 붙지 않는다.
- 중앙: 기존 전달/공용 이력 수집·조회·감시. 상시 실행은 씽크패드다.

먼저 기능별 '업무 원본/로컬 저장/서버 저장/타 폰 수신/작업 기록/원격 조회/
실행 중복 방지/오프라인/검증 증거/미완료' 목록을 작성한다. 다음 공통 기록·동기화
경로를 보완하고 그 경로에 기능별로 연결한다. 화면마다 별도 큐를 만들지 않는다.

## 완료 조건과 현재 상태

각 기능은 다음 실제 시험을 통과해야 완료로 표시한다.

1. 폰 A에서 성공·실패·취소가 기록되고 폰 B·중앙·인증된 조회에서 같은 ID/결과 확인.
2. 오프라인 저장 → 앱 종료/재시작 → 재연결 후 누락 없는 전달.
3. 중복·지연·역순·동시 편집 시 중복 실행/조용한 덮기/상태 회귀 없음.
4. 서버 장애·한 작업 오류가 다른 업무를 정지하지 않고 공백/미확정을 정직하게 표시.
5. 다른 폰에서 공유 받은 저울/출력 작업이 재실행되지 않음. 매장 권한/비밀 제외 검증.
6. 코드·테스트·DB/중앙/앱 배포·두 폰 설치·실제 관측 시각을 별도로 기록.

현재 일부 저울 진단·공용 작업함·누계·이력 경로는 존재한다. 이것은 모든 기능과
모든 폰의 동기화 검증을 의미하지 않는다. 앱 전체 계측/설정 공유/두 폰 종단 검증은
미완료이며 위 적용 목록의 조사·구현이 필요하다.

### 2026-10-15 구현·배포 구분

기초 작업 기록 확장은 +2278에 배포됐다. 이후 포함/제외 공유·설정 충돌 처리·
공용 진단 캐시/실시간 연결·실패 전달 보완은 로컬 구현이며 아직 배포하지 않았다.
운영 조사/DB 승인 대기/중앙 Git 보존 상태는
[후속 보완 기록](../plans/APP_SYNC_REPAIR_2026-10-15.md)을 따른다.

시코드 `docs/APP_SYNC_COVERAGE.md`에 기능별 조사·연결·남은 범위를 기록했다.
공통 AppActionRecorder, 미전송 진단 보존, 매장별 전달 ACK 분리, 주요 repository/
프린터/설정/업로드 경계 기록과 공유 읽기 병합을 구현 중이다.
전체 상태 수신·서버 버전 충돌·포함/제외 공유·모든 조작·두 폰 종단 시험은 미완료다.

에이전트 읽기 입구: `python scripts/app_activity_read.py --store wolgye --date 2026-10-15`
(`--feature`/`--operation-id`/`--limit` 선택). 현재 호스트의 기존 Supabase CLI 인증을
사용한다. SELECT 전용, 날짜는 한국 영업일, 서버 수신시각 기준 고정 창으로 페이지를
읽고 상한 초과면 partial이다. 원본 미관측·오프라인·미계측은 정상/행동 없음이 아니다.
쓰기/재시도/작업 상태 수정은 하지 않는다. 공통 API gateway 연결은 아직 없다.

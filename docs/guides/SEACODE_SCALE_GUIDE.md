# 시코드·저울 연결 지침

시코드 앱 상품과 CAS CL-5200 저울 PLU를 구분하고 연결·검증하는 규칙을 정의한다.

CASPi 누계 조회 경로, 날짜별 증가분과 생산·할인·매출 연결은 [통합 운영 조회 지침](DAILY_STORE_REPORT_GUIDE.md)을 따른다.

## 시스템 역할

- 시코드 앱 `products_{store}`: 매장별 상품과 운영상태의 기준
- 워터비 레시피: 상품 구성 재료와 원가의 기준
- CL-5200 PLU: 실제 저울 라벨 출력 설정
- `print_records_{store}`: 라벨 인쇄 기록이며 판매기록이 아님

## 앱 저울 업무 공통 입구 (2026-10-02)

- 현장 연결 시 상품 상세는 `refreshProduct`로 해당 PLU만 직접 읽는다. 중앙 전체
  갱신을 기다리지 않고 검증된 값을 즉시 화면에 반영하며 같은 상품 읽기는 합친다.
- 새 저울 기능도 공통 서비스와 `CaspiProtocolClient`의 직렬 통신 큐를 사용한다.
  사용자 명령은 대기 중 배경 조회보다 우선하되 진행 중 명령은 중단하지 않는다.
  화면마다 별도 소켓·재시도·쓰기 경로를 만들지 않는다.
- 기존 검증된 PLU/레코드 연결을 재사용해 중복 앱 조회를 줄이지만 CASPi의
  원본 확인·기대값 검사·ACK/read-back은 생략하지 않는다. +2262에 배포됐으며 폰 설치는 별도 확인한다.

- 화면은 `ScaleIntegrationService`로 상품·문구 변경, 상품 새로 읽기, 일일 누계를 요청한다.
  상품 자동 연동도 공통 `ScaleChangeOutboxCoordinator` 작업함에 한 번 이관한다.
- 공통 작업함은 휴대폰 SQLite에 불변 작업 ID·대상·기대값·요청값·전송 경로를 보존한다.
  작업 접수는 저울 적용 완료가 아니다. 실제 ACK와 재읽기 일치가 확인된 값만 완료로 표시한다.
- Bluetooth와 중앙 전달 모두 CASPi 실행 계약을 사용한다. 응답이 불명확하면 같은 ID의
  상태부터 확인하며 새 ID로 다시 쓰거나 중앙 직접 쓰기로 자동 전환하지 않는다.
- 상태는 대기/처리 중/적용 완료/확인 필요다. 미확정 대상만 보류하고 다른 대상은 계속한다.
  광고·성분문구 본문 확인 뒤에 해당 문구 번호를 참조하는 PLU 변경을 진행한다.
- 누계는 두 경로가 같은 파서를 사용한다. 매장·날짜·수집 ID·페이지 순서를 검사하고
  조회 도중 매장/수집 시점 변경이나 중복 PLU는 오류로 남겨 잘못된 합계 저장을 막는다.
  정상 조회한 누계의 매장·영업일별 앱 저장은 기존 누계 캐시를 사용한다.
- 이는 앱 구현 계약이다. 실제 설치 여부·Bluetooth 연결·물리 저울 쓰기 성공은
  해당 매장의 최신 운영 증거로 별도 확인한다. 과거 설치 이력을 전체 정상으로 확대하지 않는다.

### 재확인 통합 구현 / 배포 대기 (2026-10-02)

- 시코드 작업함에서 확인 필요 항목의 ‘적용 여부 재확인’을 사용한다. 문구 화면도
  같은 공통 입구를 사용하며 저장된 원래 작업 ID를 자동 선택한다.
- 새 재확인은 해당 매장 Bluetooth가 연결돼 있으면 현장, 아니면 중앙→CASPi로
  보낸다. 응답 유실 후에는 저장된 같은 재확인 ID/경로를 유지한다. 쓰기는 재전송하지 않는다.
- applied/not_applied만 해당 대상 보류를 해제한다. 다른 값·증거 부족·읽기 실패는
  보류를 유지한다. 원래 작업 이력은 보존하고 재확인 영수증을 별도로 저장한다.
- 앱·중앙 코드와 DB migration은 준비했지만 **미배포**다. 아래 과거 운영 기록의
  중앙 CLI/현장 Bluetooth 경로가 현재 설치 기준이며 새 중앙 앱 경로의 운영 성공을 주장하지 않는다.
- 사용자 요청 시에만 앱/중앙/DB를 배포한다. 실제 저울 재확인은 별도 현장 검증이 필요하다.

## 상품 연결 우선순위

1. 매장 ID
2. `mart_code` 또는 저울 상품코드
3. 명시적으로 저장된 워터비 상품·레시피 ID
4. 상품명은 확인 보조수단으로만 사용

상품명이 같아도 매장이나 코드가 다르면 같은 레코드로 단정하지 않는다.

## 상태 확인 항목

- 시코드: `id`, `name`, `mart_code`, `retail_price`, `is_active`, `is_operating`
- 워터비: Product ID, Recipe ID, 레시피 유효기간, 가격, 매장 관계
- 저울: PLU 번호, 상품코드, 상품명 1~5, 정상가격, 유효일, 분류, PLU 타입
- 운영기록: 최근 인쇄일, 생산실적, 할인·폐기 구분

## 조회와 변경 원칙

- 2026-09-30 합의: 상품 PLU 쓰기는 CASPi가 기본 실행 주체다. 휴대폰은 Bluetooth로,
  중앙 워커는 SSH로 같은 CASPi 명령과 영수증 저장소를 사용한다.
- 중앙 직접 쓰기는 예비로 보존한다. CASPi 접속 실패·응답 유실만으로 자동 전환하지 않는다.
  해당 요청의 미실행과 미확정 요청 부재를 확인하고 매장별 실행 주체를 전환한 뒤 사용한다.
  결과가 불명확하면 기존 작업 ID로 상태 확인과 저울 재읽기를 먼저 수행한다.
- 광고·성분문구 본문도 CASPi가 읽고 쓴다. 중앙 문구 워커는 요청 전달·결과 검증·앱
  스냅샷 게시를 맡고 저울 직접 쓰기는 예비로 둔다. 본문과 상품 PLU의 문구 번호는
  별도 대상이며 각각 ACK·재읽기를 검증한다.
- 2026-10-01 마포·미아·월계 라즈 설치와 중앙 워커 전환 완료. 실제 광고·성분문구
  읽기를 확인했다. 왕십리·문어팀은 접속 불가로 설치 미완료이며 문어팀 쓰기는 비활성이다.
  실제 문구 변경 ACK·재읽기와 휴대폰 오프라인 문구 편집은 아직 현장 검증 전이다.
- 광고·성분문구 확인 대기는 `reconcile_text`로 원래 작업과 백업을 확인하고 저울을
  재읽어 해제한다. 요청한 문구 또는 변경 전 원본과 일치할 때만 해당 문구를 풀고,
  다른 값·읽기 실패·증거 부족이면 유지한다. 쓰기 재전송은 하지 않는다.
  2026-10-01 복구 코드·중앙 CLI 및 마포·미아·월계 라즈 설치 완료.
  앱 문구 관리의 잠금 재확인 버튼은 Bluetooth로 같은 명령을 실행하며 작업 ID와
  결과를 휴대폰에 보존한다. 중앙 CLI도 사용 가능하나 앱의 중앙 복구 큐 연결은 없다.
  실제 잠금 해제의 현장 검증은 별도다. 왕십리·문어팀 설치는 접속 복구 후 필요하다.
- 복구 버튼 포함 앱 `1.0.4+2248` 배포 완료(실제 versionCode 4248).
  문구·복구 영수증 보관용 중앙 검증도 적용했다. 앱 업데이트 후 광고/성분문구
  관리의 잠금 재확인 버튼에서 원래 작업 ID로 확인한다. 중앙 복구는 현재 CLI 경로다.

- 시코드 상품 확인에 저울 스냅샷을 대신 사용하지 않는다.
- 저울 상태는 최신 live read-back 또는 최신 검증 스냅샷으로 확인한다.
- 캐시나 오래된 파일만 보고 현재 상태라고 단정하지 않는다.
- 불일치를 발견해도 사용자의 요청 없이 앱·저울·워터비 데이터를 임의 수정하지 않는다.
- 저울 변경은 백업, 기대값 확인, ACK, read-back, 독립 검증을 거친다.

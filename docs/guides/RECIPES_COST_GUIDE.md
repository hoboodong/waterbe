# 레시피·원가 지침

매장별 레시피, 재료, 발주규격, 가격이력과 원가 계산 규칙을 정의한다.

## 데이터 위치

- 상품: `instances/master/products.yaml`
- 재료: `instances/master/ingredients.yaml`
- 발주규격: `instances/master/purchase_specs.yaml`
- 가격이력: `instances/master/price_history.yaml`
- 매장별 레시피: `instances/master/recipes/{store}.yaml`

## 자료 구분과 점검 — 2026-10-01

‘단가’는 아래 세 가지를 구별한다.

| 자료 | 의미 | 기준 원본 |
| --- | --- | --- |
| 매입단가 | 원물·포장재 발주단위 총금액 | PurchaseSpec + PriceHistory |
| 레시피 원가 | 투입량·수율·배송비·포장재를 반영한 계산값 | Recipe + 매입단가 |
| 판매단가 | 고객에게 판매하는 가격 | 시코드 상품/저울 설정의 각 원본 |

Recipe의 `price`는 저장된 해당 기간 판매가격 참고값이다. 최신 시코드 판매가나
저울 판매가로 단정하거나 자동 덮어쓰기하지 않는다. 가격이력의 최근 날짜도
최신 매입가격이 확인됐다는 뜻은 아니다.

현재 저장 자료는 상품 61개, 재료 71개, 발주규격 102개, 가격이력 139개,
레시피 60개(마포 18·왕십리 25·월계 17)다. 미아·문어팀 레시피 파일은 없으며
다른 매장 레시피를 자동 복제하지 않는다.

읽기 전용 점검: `python scripts/inspect_recipe_data.py` (PyYAML 필요).
파일별 건수, 참조 문제, 투입량 누락, 단가이력 없는 규격을 JSON으로 반환하며
원본을 변경하지 않는다. 이 점검은 전체 스키마·원가 검증을 대신하지 않는다.

이번 점검에서 매장 참조 `atStore`가 없는 레시피 60개, 투입량/단위 미완성
항목 107개, 사용재료/발주규격 참조 누락 또는 오류 항목 42개,
가격이력이 없는 발주규격 6개가 확인됐다. 항목 수는 상품 수와 다르다.
파일명은 현재 매장 분류의 단서이지만 명시적 매장 참조와는 구별한다.
누락을 0원·사용량 0으로 처리하거나 비슷한 규격으로 임의 대체하지 않는다.

정리 순서는 매장·상품 연결 확인 → 투입량·단위 확인 → 발주규격·업체 연결 →
기준일 단가 선택 → 수율·배송비·포장재 확인 → 원가 계산이다.
완성 전에는 기존 자료/계산 가정/확인 필요를 구분해 제공한다.
이 작업에서는 과거 레시피·단가를 재작성하지 않았다.

## 재료와 발주규격

- 손실률이 `null`이면 0%로 계산한다.
- `countPerKg`가 있으면 한 개 중량은 `1000 ÷ countPerKg`이다.
- 성분 또는 알레르기가 다르면 별도 Ingredient로 분리한다.
- 납품업체만 다르면 같은 Ingredient를 사용한다.

## 가격이력

- 현재 단가는 같은 발주규격의 PriceHistory 중 기준일 이전 최신 레코드다.
- 가격이 바뀌면 기존 레코드를 수정하지 않고 새 PriceHistory를 추가한다.
- 매장 기본 납품업체 단가를 우선하고, 없을 때만 다른 업체 단가를 사용한다.
- 대영상사 배송비는 전복 박스당 5,000원, 그 외 박스당 3,000원을 별도 가산한다.

## 레시피

- 레시피는 반드시 매장과 상품을 함께 참조한다.
- 같은 매장·상품에서 현재 유효한 레시피는 최대 하나다.
- 변경 시 기존 레시피의 `effectiveTo`를 닫고 새 레시피를 추가한다.
- 양배추 1팩과 콩나물 1팩이 함께 쓰이면 `pspec_086` 양배추콩나물세트 1팩으로 원가 처리한다.

## 원가 계산

```text
실수율 = (1 - 해동손실률/100) × (1 - 손질손실률/100)
원가/g = (발주단위 가격 + 배송비) ÷ 발주단위 g ÷ 실수율
1개 원가 = 원가/g × (1000 ÷ countPerKg)
1팩 원가 = 재료별 원가 합계 + 포장재별 원가 합계
```

## 수수료와 적정원가

- 이마트 수수료: 판매가의 21.5%
- 남선푸드 수수료: 판매가의 5%
- 실수령: 판매가 × 0.735
- 적정원가 상한: 판매가 × 0.735 × 0.75, 즉 약 55.1%

할인 판매 시에는 할인된 판매가를 기준으로 수수료와 마진을 다시 계산한다.

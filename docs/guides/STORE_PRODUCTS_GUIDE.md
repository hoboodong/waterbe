# 매장·상품 지침

매장과 판매상품의 기준, 식별자, 참조 규칙을 정의한다.

## 기준 매장

| Store ID | 매장 | 약어 | 기본 납품업체 |
| --- | --- | --- | --- |
| `wangsimni` | 왕십리점 | `ws` | 남선푸드 |
| `mapo` | 마포점 | `mp` | 남선푸드 |
| `wolgye` | 월계점 | `wg` | 대영상사 |
| `mia` | 미아점 | `mi` | 미정 |
| `mooner` | 문어행사팀 (순회, 연결 준비 중) | 미정 | 미정 |

다른 파일을 참조할 때는 `instances/master/stores.yaml`에 존재하는 ID를 그대로 사용한다.

## 순회 행사팀

- `문어행사팀`은 시코드와 카스씨엘에 별도로 등록하는 독립 운영 매장이다. 전용 저울을 가지고 이동한다.
- 워터비·시코드 ID는 `mooner`, 카스씨엘 controller ID는 기존 규칙에 맞춘 `mooner2`다. 식별자 대응은 연결 완료의 증거가 아니다.
- `setupStatus: setup_pending`은 신규 연결 준비 중이라는 뜻이다. 수집기·저울·앱의 실제 연결 검증 전에는 운영 완료로 표시하지 않는다.
- 행사 장소·기간은 `instances/store_visits/mooner.yaml`의 `StoreVisit`에 추가한다. 장소를 옮겨도 팀 ID와 이전 운영기록의 귀속을 바꾸지 않는다.
- 행사 장소가 왕십리 등 기존 매장이더라도 행사팀 실적을 기존 매장의 실적으로 자동 합치지 않는다.
- 신규 상품·가격·마트코드는 확인 전까지 다른 매장에서 복제하지 않는다. 기존 남선 `행사팀` 품목 분류를 이 팀과 자동으로 동일시하지 않는다.
- 등록·연결의 현재 상태와 인수 순서는 [문어행사팀 추가 작업](../plans/MOONER_ONBOARDING.md)을 따른다.

## 상품 기준 원본

- 매장별 현재 운영상품의 기준은 시코드 앱의 `products_{store}` 테이블이다.
- 생산관리 대상은 원칙적으로 `is_active = true`이면서 `is_operating = true`인 상품이다.
- 워터비 `instances/master/products.yaml`은 온톨로지 참조용 공통 상품 목록이다.
- CL-5200 저울 PLU는 라벨 출력용 목록이며 시코드 앱 상품 목록과 동일한 것으로 간주하지 않는다.
- 앱 상품과 워터비 상품, 저울 PLU는 매장과 `mart_code`를 중심으로 연결한다. 이름만으로 자동 연결하지 않는다.

## 공통 마트코드와 매장별 등록

2026-11-05 사용자 합의.

- 남선·대영 구분 없이 상품코드는 공통이다. 각 매장에 등록되어 사용할 수 있는
  코드의 목록을 별도로 관리한다.
- 같은 코드의 명칭 변경은 공통 마트코드에 반영해 모든 매장이 공유한다.
  제공받은 매장별 자료에서 같은 코드의 명칭이 다르면 사용자에게 차이를 알리고
  해당 명칭의 통일은 보류한다. 차이가 없는 다른 코드와 매장별 등록 작업은 진행한다.
- 공통 마트코드 이름, 매장별 사용 가능 여부, 실제 앱 상품의 표시명·가격과
  저울 PLU는 각각의 담당 자료로 확인한다. 코드가 등록되어 있다는 사실만으로
  실제 판매 중이거나 저울에 반영됐다고 판단하지 않는다.

### 직원의 앱 추가·수정 경로

2026-11-05 시코드 origin/main 소스에서 확인한 동작이며, 각 폰의 설치·수신 확인은 별도다.

1. 직원이 새 코드를 추가하면 폰 로컬 공통 목록에 저장하고 현재 매장에 등록한다.
   동기화 대기 상태로 보관한다.
2. 동기화 시 코드·이름·활성값을 지원 매장의 `mart_codes_{store}`에 업로드한다.
   현재 매장 등록은 `store_mart_codes_{store}`에 별도로 업로드한다.
3. 다른 폰은 공통 목록을 내려받고, 같은 코드가 여러 테이블에 있으면
   `updated_at`이 가장 최근인 값을 선택한다. 다른 매장의 사용 등록은 별도로 추가한다.
4. 이름 수정도 전 매장 공통 목록에 전달된다. 이미 로컬에 활성 코드가 있으면
   신규 추가 화면은 중복 오류를 표시한다.

현재 다른 폰이 같은 코드에 다른 이름을 저장한 경우를 따로 알리는 기능은 없다.
업로드는 기존 값을 갱신하므로 충돌을 보존·해결하는 기능으로 간주하지 않는다.
**보완 요구사항**은 같은 코드의 서로 다른 명칭을 감지해 사용자에게 알리는 것이다.
이 요구사항은 기록 단계이며 구현·배포 완료로 안내하지 않는다.

담당 소스는 시코드의 `lib/data/local/product_dao.dart`,
`lib/features/core/settings/mart_code_manager_screen.dart`,
`lib/data/sync/modules/mart_codes_sync_operations.dart`,
`lib/data/sync/modules/store_mart_codes_sync_operations.dart`다.
실제 반영 내역과 판독 보류 항목은
[2026-11-05 등록 목록 갱신](../operations/2026-11-05-mart-codes-update.md)을 따른다.

## 상품 상태 구분

- 정상 연결: 앱 상품, 워터비 상품·레시피, 저울 PLU가 연결되고 핵심 값이 일치함
- 앱에만 있음: 시코드 운영상품이지만 워터비 또는 저울 연결이 없음
- 저울에만 있음: 저울 PLU는 있으나 시코드 운영상품과 연결되지 않음
- 정보 불일치: 상품명, 마트코드, 가격 또는 운영상태가 서로 다름
- 레시피 없음: 운영상품이지만 현재 유효한 매장 레시피가 없음
- 관리 제외: 할인, 해동중, 전처리, 숙성중, 코드확인, 테스트 등 작업용 PLU

관리 제외 여부는 이름만 보고 확정하지 말고 앱의 운영상태와 실제 용도를 함께 확인한다.

## Product 데이터

`instances/master/products.yaml`의 레코드는 기존 ID와 YAML 구조를 유지한다. 밀키트는 `prod_mk_`, 단품은 `prod_sp_`, 게장류는 `prod_gj_`로 시작하는 기존 ID 관례를 따른다.

## 변경 원칙

- 에이전트 상품 수정도 앱과 동일한 검증·원재료 연결·저장·동기화·저울 연동 규칙을
  따른다. 휴대폰 직접 조작을 요구하는 규칙이 아니다. 승인된 사진 기반 수정과
  합계 100% 검증·동기화 확인은 [품질관리 지침의 에이전트 수정 계약](QUALITY_COMPLIANCE_GUIDE.md#승인된-에이전트-상품-수정--앱과-같은-규칙-2026-10-07)을 따른다.

- 시코드 운영상품을 추가·중단했다고 해서 기존 역사 데이터를 삭제하지 않는다.
- 새 참조를 만들기 전에 대상 매장과 상품 ID가 실제 파일에 존재하는지 확인한다.
- 매장별 상품명이나 가격이 다르면 매장별 연결 정보에서 표현한다.
- 시코드 앱, 저울, 워터비 중 어느 시스템을 변경하는지 명확히 구분한다.

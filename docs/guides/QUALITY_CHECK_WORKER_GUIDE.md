# 품질점검 워커 구성 지침

2026-10-07 합의. **기획·문서화 단계이며 워커/API/자동 실행은 미구현이다.**
생산·할인·매출 연결은 이번 범위에서 제외한다.
점검 항목과 판정 기준은 [품질관리솔루션 운영 지침](QUALITY_COMPLIANCE_GUIDE.md)이
기준이다. 이 문서는 그 절차를 채팅 기억 없이 반복 실행하는 프로그램의 구성 지침이다.
새 법적 기준이나 자동 준법 인증을 정의하는 문서가 아니다.

**에이전트의 요청형 점검은 지금 실행할 수 있다.**
[즉시 실행 절차](QUALITY_COMPLIANCE_GUIDE.md#에이전트-즉시-실행--자동-워커-없이도-수행)를
읽고 조회·대조·기록한다. 미구현인 것은 자동 워커/API이며 점검 업무 자체가 아니다.

## 담당과 실행

- 워터비: 품질점검 워커, 근거 연결, 결과 저장·보고.
- 시코드: 운영상품·대표품질·원재료 구성·수정/출력 기록 원본 제공.
- 카스씨엘/CASPi: 기존 검증 경로의 저울 상품·문구 조회 증거 제공.
- 현장: 실제 사용 제품·출력본·재고 로트·보관상태 확인.
- 매장마다 별도 워커를 만들지 않는다. 하나의 품질점검 기능에 매장을 입력한다.
- 요청형 실행은 Windows/씽크패드 양쪽 모두 가능하다.
  [운영 실행 기준](OPERATING_EXECUTION_GUIDE.md)을 따른다. 자동 실행의 주기·호스트·알림은
  구현 시 별도로 정하고 같은 작업의 중복 실행을 방지한다.

## 입력 자료

1. 현재 매장의 시코드 운영상품과 상품 ID·연결정보.
2. 앱에서 실제 사용하는 대표품질 내용·공통 원재료·현재 구성 버전.
   사업 레시피로 앱 대표품질을 대신하지 않는다.
3. 저울 PLU·성분/광고 문구의 조회값·확인시각·작업/수집 증거 ID.
4. 원라벨 사진 원본 참조, 판독 내용, 제품/제조사/수입원/표시 버전,
   현재 매장에서 실제 사용하는 제품이라는 확인 근거.
5. 대표품질 수정시각·출력시각·출력기록 ID 및 실제 상품라벨/출력본 확인.
6. 현재 재고 로트·기한·실제 보관상태의 현장 확인 기록.

입력 경로·권한·스키마는 구현 전에 담당 원본에서 확인한다. 문서나 채팅에서
언급된 값만으로 현재 원본을 만들어 채우지 않는다. 사진 저장소는 기존 자료 위치를
재사용하고 원본 파일 ID·버전·접근 가능한 참조를 보존한다. 새 저장소는 아직 미정이다.

## 처리 흐름

운영상품 확인 → 대표품질 원재료 추출 → 필요한 원라벨 목록 생성 →
제품·표시 버전과 실제 사용 확인에 따라 원라벨 연결 →
앱/저울/원라벨 대조 → 출력본·로트별 현장 확인 → 문제·미확인 목록 저장·보고.

- 상품명만으로 상품/PLU를 연결하거나 원재료를 합치지 않는다.
- 동일 제품·표시 버전은 공통 결과를 재사용하되 매장별 실제 사용과 로트 기한은 따로 확인한다.
- 다른 매장의 원라벨은 참고 후보이며 현재 매장 사용 확인 전에는 확보 완료로 표시하지 않는다.
- 원라벨/OCR은 판독 초안과 확인된 내용을 구분한다. 판독 불가·모호한 성분은 추정하지 않는다.
- 자료가 부족하거나 일부 조회가 실패해도 다른 항목은 계속 처리한다.
  미조회·오래된 자료·미연결을 누락/불일치/정상과 구별한다.
- 실제 출력 모습, 소스 표시 면 노출, 재고 기한·보관상태는 서버 자료만으로 확인할 수 없다.
  증거가 없으면 현장 확인 대기로 남긴다.
- 상품·저울·대표품질을 자동 수정하거나 라벨을 자동 출력하지 않는다.
  수정은 별도 승인된 담당 절차, 이후 재점검으로 연결한다.

## 저장·변경 재점검 계약

채팅은 요청 창구이며 저장된 원본과 점검 결과가 이어가기의 기준이다.

- 점검 실행 ID, 매장, 실행/확인시각, 규칙 버전, 사용한 원본 ID·버전·해시.
- 상품–원재료–원라벨 버전의 연결 및 연결 근거, 실제 사용 확인 상태.
- 항목별 비교값·판정·미확인 사유·영향 상품·필요 조치·증거 참조.
- 원본, 판독 초안, 확인/보정, 비교 결과를 분리한다. 이전 결과는 덮어쓰지 않는다.
- 같은 입력 버전·규칙의 재처리는 중복 문제/알림을 만들지 않는다.
- 상품/공통 원재료/원라벨/출력 기록 변경 시 영향받는 상품만 재점검한다.
  상품 구성 변경은 필요한 원라벨 목록도 다시 만든다. 기한 경과는 날짜 변화로 재평가한다.
- 기존 적합 결과의 근거가 바뀌면 재확인 대상으로 돌린다.
  문제 해결은 최신 근거 대조 후 새 결과로 기록한다. 사진 수신이나 저장 ACK만으로 해결하지 않는다.
- 공통 운영 이력에는 같은 operation_id로 실행·결과·근거를 연결한다.
  담당 원본의 접근 통제된 증거 ID를 참조하고 인증/원시 오류/서명 URL은 넣지 않는다.
  저장소·실제 API 연결은 구현 때 검증하며 현재 연결됐다고 주장하지 않는다.

## 보고와 완료

폰에서 읽기 쉽게 매장·자료 기준시각과 다음 목록을 우선 보여준다.

- 필요한 원라벨: 확보·사용 확인 대기·미확보·판독 불가.
- 표시 불일치/누락: 상품·항목·서로 다른 값·영향 상품·필요 조치.
- 재출력 대상과 현장 확인 대기: 출력본·로트·보관상태.
- 조회 실패/오래된 자료와 아직 점검하지 못한 범위.

`검사 수행 완료`와 `준법 적합 완료`는 기존 품질관리 지침의 완료 조건으로 판정한다.
원라벨 목록 생성이나 자동 대조 완료는 전체 품질점검 완료가 아니다.
현장 미확인이나 원라벨 미확보가 남으면 적합으로 표시하지 않는다.
사용자 알림은 새 중요 문제·필요 조치·증거로 확인된 해결을 중심으로 설계하고
같은 미확인 항목을 반복 발신하지 않는다. 자동 Telegram 연결은 아직 없다.

## 구현 순서와 검증

1. 현재 운영상품별 필요한 원라벨·확보/사용 확인 상태 자동 목록.
2. 원라벨 제품/표시 버전 관리와 공통 원재료 영향 연결.
3. 앱·저울·원라벨 대조 및 재출력/현장 확인 대기 목록.
4. 변경 기반 재점검·내구성 이력·공통 조회 입구·선별 알림.

향후 공통 API 카탈로그에 조회/점검 실행을 분리 등록한다.
아직 호출 가능한 명령이나 API 이름을 만들어 안내하지 않는다.
동일 이름의 다른 제품, 다른 매장 원라벨, 두 버전 동시 사용, 오래된 저울 자료,
출력 기록 미동기화, 판독 불가, 중단 후 재실행, 부분 실패, 근거 변경을 검증한다.
완료는 코드 작성뿐 아니라 실제 원본 조회·결과 저장·새 세션 재조회·중복 방지·
원본 무변경·미확인 보존·근거 추적 확인까지 포함한다.

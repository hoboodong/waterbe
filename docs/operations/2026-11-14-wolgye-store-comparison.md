## 해석과 해결 순서

1. 확인된 현상은 월계의 연결 종료·재접속 및 응답 시간초과다. 공통 설정을 다른 매장 값으로 복사하는 것으로 해결할 차이는 발견되지 않았다.
2. 기존 월계 실측은 같은 연결의76개 연속 읽기 성공, 빠른 새 연결 반복 실패였다.
   중앙 전체 조회까지 CASPi 연결 소유자에 모아 요청 간 연결 재사용과 순차 응답 처리를 해야 한다.
3. 실패한 배경 조회가 계속 새 연결을 만드는 흐름은 억제하고 현장 요청을 우선한다.
   매 요청 고정20초 지연이나 미확정 쓰기 자동 재전송을 넣지 않는다.
4. socket connect/첫 응답/EOF/RST/프레임 검증 오류를 구분해 남긴다. 현재 상위 ValueError/backup exit1만으로 원인 구분이 어렵다.
5. 통합 경로 검증 뒤에도 월계만 재발하면 정상 매장과 저울 펌웨어·통신 설정을 대조하고,
   LAN 케이블/포트 교차 시험과 양단 패킷을 통해 장비·물리 구간을 분리 진단한다.
   현재 펌웨어 버전 및 물리 교차 시험은 미확인이다.
6. 실제 reporter는 실패2회→이상, 성공1회→복구다. 단발 성공과 안정 회복을 구분하도록 보완한다.
   이는 알림 정확도 개선이며 연결 장애 자체의 해결을 대신하지 않는다.

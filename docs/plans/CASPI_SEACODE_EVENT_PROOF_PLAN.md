# CASPi·시코드 사건 증명 및 무중단 복구 기획안

기준일: 2026-09-28
상태: 코드·서버 계약 구현 / 현장 장비 배포·통합시험 대기

## 목표

저울에서 읽기 또는 쓰기 변화가 한 번 발생하면 같은 사건을 CASPi, 시코드,
Supabase, 카스씨엘 중앙이 연쇄적으로 증명한다. 주기적인 전체 대조가 아니라
변화가 다음 단계를 깨우는 사건 기반 구조를 사용한다.

휴대폰 인터넷과 Pi 인터넷은 서로 독립적으로 취급한다. 어느 한쪽만 인터넷에
연결되어도 동일한 CASPi 영수증을 서버에 전달할 수 있어야 하며, 두 경로가
동시에 살아 있어도 저울 작업은 한 번만 실행한다.

## 확정 원칙

1. CASPi가 저울 작업의 단일 실행자이자 영수증 원본이다.
2. 읽기·쓰기는 하나의 `operation_id`로 CASPi에서 최대 한 번 실행한다.
3. 시코드 경로와 중앙 경로는 실행 경로가 아니라 동일 영수증의 독립 전달
   경로가 될 수 있다.
4. CASPi는 Supabase에 직접 접속하지 않으며 Supabase 자격증명을 갖지 않는다.
5. 휴대폰 인터넷이 되면 시코드가 게시하고, Pi 인터넷이 되면 중앙 워커가
   CASPi에서 회수해 게시한다.
6. Supabase는 `operation_id`와 영수증 해시로 중복을 병합하고 다른 내용은
   충돌로 거절한다.
7. 모호한 쓰기는 자동 재실행하지 않는다. 해당 작업 또는 해당 PLU만 격리하고
   조회, 다른 PLU 작업, 영수증 동기화는 계속한다.
8. 잠금은 시간만으로 강제 해제하지 않는다. 저울 재조회로 현재 상태가
   증명되면 자동 해제하고, 어느 상태와도 맞지 않을 때만 관리자 확인을 받는다.

## 전체 흐름

```text
CL-5200
   ↕ 유선
CASPi ── Bluetooth ── 시코드
  │                     │
  │ Pi 인터넷           │ 휴대폰 인터넷
  ↓                     ↓
카스씨엘 중앙 ───────→ Supabase
```

현장 작업은 블루투스를 우선한다. 블루투스가 작업 전 연결되지 않았고 인터넷이
있으면 시코드가 중앙 원격 경로를 선택할 수 있다. 전송 후 연결이 끊겼다면 새
경로로 다시 실행하지 않고 같은 `operation_id`의 상태를 먼저 복구한다.

## 사건과 증명 단계

CASPi 영수증은 다음 식별정보를 가져야 한다.

- `operation_id`: 실행과 재접속에 공통으로 쓰는 UUID
- `store_id`, `device_id`, 명령, 대상 부서·레코드·PLU
- 요청 내용의 정규화 해시
- 변경 전·후 payload 해시와 검증 결과
- 저울 ACK와 재조회 결과(쓰기인 경우)
- CASPi 완료시각과 `receipt_hash`
- 향후 장치 서명을 위한 서명 버전·키 ID

증명 단계는 서로 덮어쓰지 않고 누적한다.

```text
CASPi 실행·검증
→ 시코드 로컬 저장
→ 시코드 또는 중앙의 Supabase 게시
→ 중앙 원본 대조
→ 최종 확인
```

연결 상태 하트비트는 장치가 살아 있다는 정보일 뿐 작업 증명이 아니다. 화면과
데이터에서 연결 상태와 영수증 증명을 구별한다.

## 인터넷 조합

| 휴대폰 인터넷 | Pi 인터넷 | 영수증 게시 경로 |
| --- | --- | --- |
| 가능 | 가능 | 먼저 도착한 경로 저장, 나중 경로는 같은 영수증 추가 확인 |
| 불가 | 가능 | 중앙 워커가 CASPi에서 회수해 게시 |
| 가능 | 불가 | 시코드가 Bluetooth 수신 후 게시 |
| 불가 | 불가 | CASPi와 시코드 outbox에 보관, 먼저 복구된 경로가 게시 |

두 게시자가 같은 `operation_id`에 같은 영수증을 올리는 것은 성공적인 멱등
재전송이다. 해시나 내용이 다르면 자동 선택하지 않고 충돌 증거로 보존한다.

## 쓰기 단일 실행

쓰기 요청은 경로 선택 전에 로컬에 저장한다. CASPi는 작업 ID를 저울 I/O 전에
영속적으로 선점하고 하나의 큐와 하나의 저울 잠금으로 직렬화한다.

- 동일 ID·동일 요청: 저장된 영수증 반환
- 동일 ID·다른 요청: 충돌 거절
- 다른 요청·같은 PLU: 먼저 실행 중인 작업 뒤에서 현재값 재검증
- 기대값 불일치: 쓰지 않고 해당 요청만 보류
- 쓰기 전송 후 단절: 재전송 금지, 재조회 복구

시코드와 중앙이 동시에 같은 사건을 전달해도 실행은 한 번이다. 서로 다른 쓰기
요청이 같은 PLU를 대상으로 하면 두 번째 요청은 첫 작업 이후의 실제 현재값과
자신의 기대값을 비교한 뒤에만 실행할 수 있다.

## 격리와 잠금 해제

잠금 범위를 전체 시스템이 아니라 최소 단위로 나눈다.

- 저울 I/O 잠금: 명령 전송 동안 짧게 전체 저울 잠금
- 작업 잠금: 해당 `operation_id`의 중복 실행 방지
- PLU 격리: 결과가 불명확한 쓰기의 대상 PLU만 후속 쓰기 금지
- 게시 대기: 서버 전송만 대기하고 저울 기능은 계속

불명확한 쓰기는 저울을 다시 읽어 다음처럼 정리한다.

| 재조회 결과 | 처리 |
| --- | --- |
| 요청한 변경 후 값과 일치 | 성공 확정, PLU 격리 해제 |
| 변경 전 값과 일치 | 미실행 확정, PLU 격리 해제 |
| 어느 쪽과도 불일치 | `needs_review` 유지, 관리자 판단 |

프로세스 재시작 시 실행 전 종료된 작업은 취소 가능하지만, 프레임 전송 여부가
불명확한 작업은 반드시 재조회한다. 강제 해제는 관리자 전용이며 사유, 작업 ID,
현재 저울값과 실행자를 감사기록에 남긴다.

## 생산량 메뉴 연결

시코드 생산량 메뉴에서 CASPi 누계는 수정 불가능한 `저울 관측값`으로 보인다.
직원이 적용하거나 보정한 값만 `확정 생산량`이 된다.

```text
문어탕
저울 14개 · 333,200원
확정 14개 · 폐기 2개

증명: CASPi ✓  휴대폰 ✓  서버 ✓  중앙 ✓
```

라벨 수, 저울 수량, 중량과 금액을 별도 필드로 보존한다. 한 라벨에 수량 여러
개, 중량상품, 오출력·재출력, 전환을 라벨 수 하나로 확정하지 않는다.

## 현재 구현과 남은 차이

이미 존재하는 기반:

- CASPi RFCOMM/SPP와 `operation_id` 영속 선점
- 동일 ID 중복 실행 방지와 `operation_status`
- 쓰기 ACK·즉시 read-back·비대상 필드 검증
- 시코드 로컬 outbox와 서버 게시 재시도
- `local_bluetooth` / `central_remote` 경로 구분
- Supabase 영수증 중복 방지와 내용 충돌 거절

2026-09-28 구현됨:

1. CASPi 영수증 cursor와 중앙 회수 워커
2. 시코드·중앙의 동일 영수증 이중 게시 및 충돌 거절 서버 계약
3. 대상 PLU 격리와 `applied`·`not_applied`·`needs_review` 재조회 판정
4. 날짜별 누계 증가분과 기준선·수집공백 품질정보
5. 생산량 화면의 품목별 라벨·수량·중량·금액 관측값 표시와 검증값 적용

남은 현장·보안 작업:

1. 각 Pi에 새 CASPi 패키지 설치와 중앙 회수 워커 운영 설정
2. 앱 새 버전 현장 설치 및 Bluetooth 읽기 통합시험
3. 허가된 시험 PLU 쓰기·원복과 인터넷 네 조합 시험
4. CASPi 장치 서명과 키 등록·회전 절차

## 구현 순서와 완료 조건

### 1단계 — 공통 사건 계약

- 기존 영수증과 호환되는 사건·게시 확인·충돌 상태 정의
- 동일 영수증의 시코드/중앙 이중 게시 테스트
- 다른 영수증의 같은 ID 충돌 테스트

### 2단계 — 중앙 회수 경로

- CASPi durable cursor 또는 outbox에서 중앙이 새 영수증만 회수
- Pi 인터넷만 있는 상황에서 중앙 게시 검증
- 중앙 장애 후 누락된 순번만 재개

### 3단계 — PLU 격리와 복구

- 모호한 쓰기 발생 시 해당 PLU만 격리
- 전·후·제3값 재조회 세 경우 검증
- 다른 PLU와 읽기·누계가 계속되는지 확인

### 4단계 — 생산량 화면

- Bluetooth 누계 수신, 앱 상품 연결, 저울 관측값 표시
- 현장 적용·보정·폐기와 원본 분리 저장
- 증명 단계와 최신 자료시각 표시

### 5단계 — 실제 매장 승인

- 읽기 전용 현장시험
- 허가된 시험 PLU 한 필드 변경과 정확한 원복
- 휴대폰/Pi 인터넷 네 조합과 블루투스 단절 시험
- V1 쓰기 소유권 종료 후에만 CASPi 쓰기 활성화

완료는 코드 작성만이 아니라 실제 장비에서 중복 실행 없음, 오프라인 복구,
충돌 격리, 다른 업무 지속, 서버 병합과 모바일 표시까지 확인한 상태다.

# 통합 운영 프로그램 작업 지시서

작성일: 2026-09-26 · 상태: 초안 / 실행 승인 전

첫 검증 대상은 2026-09-26 사용자 선택에 따라 **월계점 오늘 생산량**으로 변경했다. 이번 실제 조회의 대상일은 2026-09-26(KST)이며, 이후 `오늘`은 요청 시점의 한국 날짜로 고정한다. 읽기 전용 조회 검증과 아래 구현 작업의 착수·배포 승인은 구별한다.

## 0. 이 문서의 사용 범위

현재 요청은 **작업 지시 작성만**이다. 아래 작업을 지금 시작하거나 다른 프로젝트에 실행 지시로 전송하지 않는다. 구현·운영 DB 변경·권한 변경·배포·서비스 재시작·커밋·푸시는 하지 않는다.

사용자가 작업 번호와 착수 범위를 승인하면 해당 묶음만 수행한다. 로컬 구현 승인과 운영 반영 승인은 구별한다. 미해결 선행조건을 추측으로 채워 다음 단계까지 진행하지 않는다.

특정 작업을 발췌해 전달할 때도 이 절과 공통 지시를 함께 전달하고, 승인된 작업 번호·변경 가능 범위·운영 반영 제외 여부를 명시한다. 아래 명령형 문장은 승인 후 수행할 요구사항이지 현재 실행 요청이 아니다.

- 총괄: **Waterbe**. 업무 규칙, 공통 계약, 통합 계산, 최종 인수를 책임진다.
- 카스씨엘: 저울 수집·관측값·기간 증가분·수집 품질의 제공을 책임진다.
- 시코드: 운영상품·가격·상품 연결·출력/취소 원본의 제공을 책임진다.
- 기준 문서: [프로그램 역할](../guides/PROGRAM_RESPONSIBILITIES_GUIDE.md), [통합 기획안](INTEGRATED_OPERATIONS_QUERY_PLAN.md), [운영 조회 규칙](../guides/DAILY_STORE_REPORT_GUIDE.md).
- 각 담당자는 자기 프로젝트의 `AGENTS.md`와 관련 지침을 먼저 읽는다. 다른 프로젝트 내부 파일을 임의 수정하거나 고정 절대경로로 import하지 않는다.

## 1. 작업 순서와 배정

| 작업 번호 | 담당 | 목적 | 선행조건 |
| --- | --- | --- | --- |
| WB-00 | 워터비 주관, 카스씨엘·시코드 검토 | 공통 계약·읽기 경로·접근권한 범위 확정 | 별도 착수 승인 |
| CAS-01 | 카스씨엘 | 기간별 검증된 저울 관측값 제공 | WB-00 계약 합의 |
| SEA-01 | 시코드 | 상품·연결·출력 원본 제공 | WB-00 계약 합의 |
| WB-01 | 워터비 | 월계 생산 조회·공통 계산 기반 | WB-00; 실제 인수는 CAS-01·SEA-01 필요 |
| WB-02 | 워터비 | 월계 현장보고·할인·전환·폐기 | WB-01, SEA-01 할인 계약 |
| WB-03 | 워터비 | 실제 매출 연결·4개 매장 확대 | WB-01; 종합 인수는 WB-02 필요 |
| WB-04 | 워터비 총괄, 전송부 담당 협력 | 새 대화·모바일·실제 자료 인수 | WB-01~03 및 별도 운영 연결 승인 |
| WB-05 | 워터비 | 정기 갱신 워커·보관 결과 자동 갱신 | WB-04 통과 후 필요성·범위 별도 승인 |

CAS-01과 SEA-01은 병렬 진행할 수 있다. WB-01의 고정 샘플 기반 개발도 병행할 수 있지만, 샘플 통과를 실제 원본 연결 완료로 보고하지 않는다. 첫 사용자 기능은 월계 생산 조회이며, 이후 월계 할인·현장정보, 실제 매출·4개 매장 순서로 인수한다.

## 2. 모든 작업에 적용할 지시

1. 기존 수집·매출 동기화 기능을 재사용한다. 새 수집기나 별도 계산 체계를 중복 구현하지 않는다.
2. 조회는 읽기 전용이다. 원본 동기화, 현장기록 저장, 보고 결과 저장, 운영 배포는 각각 별도 동작으로 구분한다. 저장 기능은 승인된 대상에만 쓴다.
3. 조회 실패·미게시·오래된 자료·부분 범위·확인된 0을 구분한다. 실패와 불명 값은 `null`이며, 옛 계획량이나 전날 자료로 대체하지 않는다.
4. 원본 ID·수집/수정시각·조회시각·매장·기간·계약/계산 버전·보정 근거를 보존한다. 요청 접수 때 한국 날짜를 고정한다.
5. 원본과 현장보고를 덮어쓰지 않는다. 정정은 이전 기록과 연결하고, 동일 메시지·출력·수집 회차의 중복 반영을 막는다.
6. 계정은 필요한 매장·테이블·열의 최소 읽기 범위를 설계한다. 권한 오류 해결을 이유로 공개 권한 확대, RLS 해제, 토큰 복제·출력, 비밀번호 반복 시도를 하지 않는다.
7. 기존 사용자 변경을 보존한다. 원시 DB·대량 인쇄 원본·개인정보·자격증명은 Git이나 테스트 fixture에 넣지 않는다. fixture는 필요한 최소 자료 또는 합성 사례로 만든다.
8. 조회 명령은 DB/저울/앱 쓰기, Drive 정리, OCR 재적재, 설치·업데이트·서비스 재시작을 유발하지 않게 한다.

## 3. WB-00 — 공통 계약과 사전 점검

**담당:** 워터비. 카스씨엘·시코드는 자기 원본에 대한 계약을 검토한다.

**작업 지시**

1. 요청/응답 계약 v1을 문서와 기계 검증 가능한 스키마로 작성한다. 이름은 이 단계에서 합의하며, 제안 필드가 현재 DB 컬럼이라고 가정하지 않는다.
2. 요청에는 매장, 영업일, 시간대, 고정 기준시각, 요청 항목, 요청 ID를 포함한다. 인증된 호출자 정보는 전송부에서 전달받고 메시지 본문의 이름으로 권한을 판단하지 않는다.
3. 응답에는 품목별 값·단위·근거, 확인 소계와 전체 합계의 구별, 출처 ID·시각·버전, 미확인 항목을 포함한다. 접근 성공, 최신성, 기간 완전성, 실제/신고/추정 상태를 별도 항목으로 정의한다.
4. 카스씨엘의 실제 실행 호스트·중앙 DB·허용된 읽기 대체 경로, 시코드 실제 조회 경로, 매출 조회 경로를 목록화한다. 씽크패드에 Windows DB가 있다고 가정하지 않는다.
5. 현재 권한으로 무엇이 읽히는지 점검하고, 부족한 경우 필요한 최소 권한과 담당 프로젝트를 제안서에 적는다. 이 단계에서 운영 권한을 변경하지 않는다.
6. 매장 ID 대응, 상품 ID 네임스페이스, 가격/중량 단위, 수량·라벨 장수의 뜻, 페이지 완결, 시간 제한·재시도·캐시 정책을 합의한다.

**산출물:** 계약 v1, 출처/호스트/권한 목록, 정상·부분·실패 예제, 공통 fixture 및 기대 결과, 미결정 사항과 결정 담당자.

**완료 조건:** 세 프로젝트가 같은 예제를 같은 의미로 해석한다. 미정인 접근 경로·단위·권한은 명시되고 해당 기능의 실제 연결 인수는 보류된다. 다른 담당자가 대화 이력 없이 계약만 읽어 호출·검증 방법을 이해한다.

## 4. CAS-01 — 날짜별 저울 관측 조회

**담당:** `cascl5200`. 워터비에는 표준 호출 방법과 결과만 제공한다.

**입력:** 등록 매장, 시작/종료 시각의 반개구간 `[start, end)`, 기준시각, 계약 버전. KST 날짜를 UTC로 변환한 양쪽 경계를 유지한다.

**작업 지시**

1. 기존 중앙 자료를 읽는 조회 실행부를 구현한다. 우선 실제 확인된 중앙 SQLite의 읽기 전용 연결·일관된 트랜잭션을 검토하고, 실행 위치를 설정으로 분리한다.
2. 최신 누계 합계 대신 검증된 구간 증가분을 반환한다. 시작 직전 기준선·종료 경계·수집 공백·카운터 감소·PLU 기준선 누락을 검사한다.
3. `A→C` 뒤 `B`가 늦게 들어온 경우 선행 회차를 검증하고 정렬된 원본으로 조회 결과를 재계산하거나 일관성 오류를 반환한다. 저장 DB를 조회 과정에서 고치지 않는다.
4. 정상 빈 회차와 실패를 구분한다. 기존 검증된 초기화/0 기준선 규칙을 적용하고, 첫 관측이나 동일 PLU 기준선 부재를 무조건 0으로 채우지 않는다.
5. 날짜를 가로지르는 증가분을 오늘 몫으로 임의 배분하지 않는다. 공백 구간의 증가분을 보존할 수 있는 경우와 일자 귀속이 불가능한 경우를 구분한다. 실패 로그가 없으면 공백 원인을 추측하지 않는다.
6. 원시 카운터별 단위·배율을 검증한다. 수량·라벨 장수·중량·금액은 서로 다른 값으로 제공한다. 작업용 PLU의 적용 근거·정책 버전·유효범위를 반환하되 원본은 보존한다.
7. 클라우드를 소스로 사용할 경우 헤더·원본·증분의 완결을 검사하는 경계를 먼저 제공한다. 헤더만 있는 회차를 완료로 판정하지 않는다.

**출력/산출물:** 매장·부서·PLU별 원시 값과 검증 구간 값, 단위, 선행/현재 회차 ID·시각, 기준선·공백·범위 상태, 오류 코드; 버전 있는 호출 문서, 실행부, fixture·테스트 결과, 호스트별 실행/의존성 안내. 값은 ‘저울 관측값’으로 명명하며 최종 생산량·실제 매출로 명명하지 않는다.

**필수 테스트:** 최초 기준선 부재, 정상 빈 회차 뒤 증가, 카운터 감소, PLU 사라짐/재등장, 자정 교차, 다일 공백, 지연 B 삽입, UUID 중복, 부분 게시, 단위 미확정. 같은 원본에서 중복·음수·임의 0 보정이 없어야 한다.

**금지:** 저울 명령·PLU 변경·누계 초기화, 새 수집기/중복 스케줄러, 중앙 DB 수정, 호스트 이전·서비스 변경, 워터비 사업 계산의 복제.

## 5. SEA-01 — 상품·연결·할인 원본 조회

**담당:** `seacode_new`. 데이터 제공 책임이며 워터비의 사업 계산을 앱에 복제하지 않는다.

**입력:** 허용된 매장, 기준시각/대상 기간, 요청 데이터 종류, 계약 버전, 페이지 조건.

**작업 지시**

1. 실제 운영 스키마를 확인하여 `products_{store}`, 기존 binding, `print_records_{store}`, 앱 생산 입력을 제공할 읽기 경계를 정한다. 기존 뷰를 쓸지 어댑터를 쓸지와 최소 권한 범위를 제출한다.
2. 상품 ID·매장·마트코드·상품명·가격과 가격단위·활성/운영 상태·삭제 상태·변경시각을 제공한다. 역사적 조회에 필요한 비운영/삭제 상품을 현재 운영목록 필터로 숨기지 않는다.
3. 기존 binding의 ID·매장·상품·부서·PLU·상태·해제·검증시각·확인 가능한 스냅샷 참조를 제공한다. 활성 연결의 중복/충돌을 검증하고 해제·미연결과 구별한다. 과거 유효기간이 없으면 ‘현재 연결’이라고 명시한다. 이름만으로 binding을 새로 만들거나 과거 연결을 추정 확정하지 않는다.
4. 할인에는 매장과 이벤트 ID의 복합 식별자, 출력/수정시각과 확인 가능한 수신시각, 상품/코드, 최초가격·작업기준가격·최종가격·정확한 할인액, 할인율, 라벨 장수, 작업 건수, 취소 상태, 단계, 바코드, 스키마 버전을 제공한다. 원 단위 처리와 단가/작업 총액의 의미를 명시하고 재할인 전 기준가격과 최초 정상가를 혼동하지 않는다.
5. 기존 통합 뷰와 원본의 할인 단계 노출 차이를 처리한다. 구형 이벤트 수량과 NULL 취소값은 의미를 검증한 호환 규칙으로만 해석한다. 미지원 자료는 미지원 상태로 반환한다.
6. 출력 1행이 N장 요청 작업일 수 있고 취소가 작업 전체에 적용됨을 보존한다. 요청 장수가 실제 배출 성공·부착 성공을 보증하는지도 구별한다. `discount_stage=1/2`와 동일 바코드만으로 개별 물건의 재할인 계보를 만들지 않는다.
7. 늦은 업로드·사후 취소·복원을 놓치지 않게 대상일 전체 재조회, 안정된 정렬, 페이지 완결·변경 충돌 검사를 마련한다. 클라이언트 `updated_at`만으로 신뢰 가능한 서버 변경 커서라고 주장하지 않는다.
8. 앱 생산 입력은 `expected_qty`, `actual_qty`, `waste_qty`를 구별해 제공한다. 실제 부착·개별 상품 계보가 원본에 없으면 ‘없음/미확인’으로 명시하고 필요한 입력 보완은 별도 변경안으로 제출한다.

**출력/산출물:** 상품·binding·할인·앱 신고 계약, 버전 있는 조회 경계, 필드 의미/호환표, 권한 변경 필요안, fixture·테스트 결과. 운영 스키마·권한 변경은 별도 승인 후 적용한다.

**필수 테스트:** 1행 N장, 작업 전체 취소/복원, 과거일 지연 업로드, 상품 ID 없음, 동일 바코드의 다른 물건, 단계 중복, 연결 해제, 과거 이력 없음, 페이지 중간 실패, 허용되지 않은 매장 접근. ‘출력’을 ‘부착/판매’로 반환하는 경로가 없어야 한다.

**금지:** 상품·가격·PLU·binding 임의 수정, 모든 계정에 읽기 공개, 없는 과거 이력 생성, 새 부착 UI/생산관리 화면의 무단 추가.

## 6. WB-01 — 월계 생산 조회와 공통 계산 기반

**담당:** `waterbe`. 요청형 조회부터 구현하며 상시 워커는 만들지 않는다.

**작업 지시**

1. 조회 진입점과 읽기 전용 사전점검 기능을 만든다. `report`, `doctor`는 제안 명칭이며 실제 명령·설치 위치는 WB-00에서 확정한다.
2. 카스씨엘·시코드 계약을 소비하는 어댑터, 정규화, 사업 계산, JSON 결과, 모바일 렌더러를 분리한다. 샘플 소스와 실제 소스를 명확히 구별한다.
3. 요청한 항목에 필요한 원본만 조회한다. 생산 질문을 불필요한 매출 장애 때문에 전부 실패시키지 않는다. 인증 실패는 짧게 종료하고 전체 시간 예산을 지킨다.
4. 매장·부서·PLU·코드·binding·명시적 Waterbe ID로 연결한다. Waterbe `prod_*`와 시코드 ID를 같은 ID로 취급하지 않는다. 미연결·예외 상품도 식별자와 값이 있는 별도 행으로 유지한다.
5. 저울 관측, 현장 신고, 실제 확인, 추정을 별도로 유지한다. 중량상품의 수량 0을 생산 없음으로 해석하지 않는다. 현재 가격/연결을 역사적 조회에 무조건 소급하지 않는다.
6. 동일 원본 버전·현장정보·기준시각·계산 버전에는 같은 계산 결과를 반환한다. 금액/중량 정밀도와 반올림 규칙을 고정하고 품목합과 총액을 검산한다.
7. 초기 현장정보는 기존 운영 YAML을 읽는다. 이 단계에서 기존 기록을 새 구조로 일괄 재작성하지 않는다. 원본 대량 복제 없이 결과의 출처와 계산 버전을 추적할 보관 형식을 제안한다.

**출력/산출물:** 요청형 조회·사전점검 기능, 어댑터/계산/렌더러, 전체 품목 JSON·모바일 예제, 단위·금액·공백·실패 테스트, 실제 연결 미완료 목록.

**완료 조건:** 월계의 확인 가능한 관측 구간을 재현하고 미확인 범위를 숨기지 않는다. 품목 이름/식별자·수량/라벨·중량·금액·출처시각을 출력하며 상위 품목만 보여주지 않는다. 샘플 통과와 실제 조회 성공을 별도로 보고한다.

## 7. WB-02 — 현장보고·할인·전환·폐기

**담당:** `waterbe`. 우선 월계 규칙과 기존 운영기록을 연결한다.

**작업 지시**

1. 조회와 분리된 현장기록 입력/정정 경계를 만든다. 매장·영업일·상품·원문/메시지 ID·입력단위·추가/총량/정정 구분·확인시각·대체 기록 ID를 남긴다. 같은 메시지 재수신은 한 번만 반영한다.
2. 기존 YAML을 초기 현장 저장소로 유지한다. 동시 쓰기 방지·원자 저장·ID/매장일 중복 검증·실패 복구를 먼저 갖추고 임시 fixture에서 시험한다. 실제 운영기록 변경은 사용자 입력 범위만 반영한다.
3. ‘팩=원물 투입, 개=완제품’을 기본으로 하되 명시된 예외가 우선이다. 박스 구성·팩당 중량·관자 알 수·포장중량·수율을 날짜/생산분별 기준으로 관리한다. 근거가 없으면 환산을 지어내지 않는다.
4. 앱 신고·대화 신고·저울 관측이 같은 생산이면 이중 가산하지 않는다. 연결 근거가 불명확하면 대조 항목으로 남긴다. ‘추가’, ‘현재 총량’, ‘이전 수량 정정’을 다른 동작으로 처리한다.
5. 할인은 출력·사전 출력·부착·오출력·취소·미확인으로 나눈다. 사용자 확인을 해당 매장·영업일·출력 묶음·장수에 연결하며, 40% 사전 출력 지시를 다른 날로 자동 이월하지 않는다.
6. 같은 물건이라는 근거가 있는 재할인만 이전 단계를 대체한다. 당일 생산 귀속·이월재고·미확인을 분리하고, 출력장수나 실제 대상수량을 넘는 매칭은 금지한다.
7. 전환은 원상품·대상상품·수량/중량·시각·근거를 연결해 중복 생산금액만 조정한다. 폐기는 별도로 기록하고 이미 적용한 할인액을 중복 차감하지 않는다. 약수량은 추정으로 보존한다.
8. 생산금액, 조정 생산금액, 최종 부착 할인액, 할인후생산금액, 폐기를 별도 계산한다. 부착·귀속이 불명확하면 전체 확정액 대신 확인 소계/조건을 반환한다. 라벨로 추정한 판매량을 실제 매출로 저장하지 않는다.

**산출물:** 현장 이벤트/정정 계약과 저장기, 기존 YAML 읽기 호환, 날짜별 환산 규칙, 할인·전환·폐기 계산, 근거별 재계산 이력, 회귀 테스트.

**필수 테스트:** 원물 8팩+추가 2팩, 총량 정정, 포장수량 명시 예외, 관자 구성 변경, 라벨 1장에 수량 7, 신고 재전송, 앱/대화 이중 신고, 500g/일반 중량상품의 확인된 합산, 다단계 할인, 40% 미부착/일부 부착, 반품 후 재부착, 전환 후 폐기, 동시 쓰기 실패. 예시는 테스트용이며 현재 영업일에 기록하지 않는다.

## 8. WB-03 — 실제 매출과 4개 매장

**담당:** `waterbe`. 기존 남선·대영 검증자료를 읽는 기능이며 새로운 OCR/수집기를 만들지 않는다.

**작업 지시**

1. 남선/대영 자료를 읽는 어댑터에 매장·영업일·자료 집계일·원본 ID·검증상태·수수료/세금/행사팀 범위를 포함한다. 최신 자료일을 요청 영업일과 구별한다.
2. 남선은 상품행과 매장합계행을 함께 더하지 않고, 월누계를 일별 합산하지 않는다. 월 조회는 기존 지침의 마지막 자료 월누계 기준을 유지한다. 행사팀 분리와 점포코드 대응도 기존 검증 규칙을 사용한다.
3. 대영 `review_required` 금액은 확정 매출에서 분리한다. 상품 필드가 없는 자료를 품목별로 임의 배분하지 않고, 월계 매장·일자 합계까지만 비교한다.
4. 월계의 21.5% 수수료 차감 기준이 대상 자료에도 유효한지 확인한 뒤 `차감 후 금액 ÷ 0.785`로 비교 기준을 맞춘다. 비율과 유효기간을 기록하고 다른 매장에 자동 적용하지 않는다.
5. 자료 미게시·검토 대기·휴무·실제 0을 구분한다. 이월재고와 품목/기간 범위 차이를 표시하고 생산과 매출의 차액을 이익·손실·재고로 단정하지 않는다.
6. 왕십리·월계·마포·미아를 같은 계약으로 검증한다. 한 매장 또는 한 출처의 실패가 다른 정상 값을 지우지 않도록 한다.

**산출물:** 읽기 전용 매출 어댑터, 비교 기준 계약, 4개 매장별 검증표, 일/월 집계·검토대기·범위 불일치 테스트.

**완료 조건:** 매장·날짜·금액 기준이 맞는 경우에만 비교하며 출처까지 역추적된다. 조회가 Drive 파일 이동/중복 휴지통 처리, OCR 실행, 날짜별 재적재를 유발하지 않는다.

## 9. WB-04 — 실제 자료·새 대화·모바일 인수

**담당:** 워터비 총괄. 전송부는 실제 저장소·실행 주체 확인 후 별도 승인된 범위에서 협력한다.

1. 계약·계산 버전을 고정하고 아래 인수표의 결과·기준시각·원본 참조·미확인 이유를 남긴다. 실제 자료는 재조회하고 테스트용 최소 스냅샷을 보관해 이후 수정과 구별한다.
2. 이전 대화를 모르는 새 세션에서 고정 진입점만으로 같은 조회를 실행한다. 필요하면 기존 지침의 연결만 갱신하며 계산/접속법을 대화마다 다시 만들지 않는다.
3. 모바일 출력은 매장·날짜·출처시각, 전체 품목, 합계, 확인사항 순서로 만든다. 긴 목록은 분할하되 생략하지 않는다. 구조화 결과를 모델이 임의로 재계산하지 않게 한다.

5. 운영 연결 전에 실행 호스트·계약 버전·자격증명 참조·중단/되돌림 방법을 제출한다. 기존 수집기를 그대로 유지한다. 서비스 이전/배포/재시작과 실제 텔레그램 테스트 전송은 별도 승인 후 시행한다.

## 10. WB-05 — 정기 갱신 워커는 후속 승인 대상으로 둔다

첫 출시에서 필수 구현하지 않는다. WB-04 이후 다음 범위를 승인받았을 때만 착수한다.

- 요청형 조회와 **같은 계산 함수**를 주기적으로 실행하고 원본별 신규/변경 여부를 확인한다.
- 늦은 업로드·사후 취소·정정이 과거 날짜에도 들어올 수 있으므로 오늘 자료만 검사하지 않는다. 신뢰 가능한 변경 커서 또는 전체 대조 전략, 대상기간, 주기, 보관기간을 먼저 확정한다.
- 출처/계산 버전을 키로 중복 실행을 막고, 실행 중 충돌·중단 후 재시도·오래된 결과 표시를 검증한다. 성공한 결과만 승인된 결과 저장소에 원자적으로 갱신한다.
- 원시 데이터의 수집/적재를 중복 실행하지 않는다. CASPi/시코드/매출 동기화 타이머를 워터비 워커로 대체하지 않는다.
- 사용자 알림, 자동 보고 발송, 가격·발주·재고 조정은 이 워커에 자동 포함하지 않는다.

## 11. 담당자가 제출할 완료 보고 형식

각 작업은 다음 항목으로 보고한다.

1. 작업 번호, 담당 프로젝트, 실제 변경 파일/버전.
2. 구현한 기능과 아직 제안/미구현/미배포인 기능.
3. 입력·출력 예제 및 적용한 계약/계산 버전.
4. 실행한 테스트와 결과, 실제 조회 근거·시각, 미실행 테스트와 이유.
5. 원본/운영 서비스 변경 여부, 남은 권한·연결 문제, 후속 승인 필요 항목.

현재 완료된 것은 **이 작업 지시서 작성**뿐이다. 위 작업 번호는 모두 미착수이며 다른 프로젝트에 구현 지시를 발송하지 않았다.

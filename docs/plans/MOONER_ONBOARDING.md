## 사용자 확인과 범위

- 문어행사팀은 장소를 옮겨 다니는 독립 운영팀이다.
- 팀 전용 저울을 가지고 이동한다. 카스씨엘에도 새 연결이 필요하다.
- 시코드·카스씨엘·워터비에 신규 매장을 추가하는 전체 작업을 요청했다.
- 2026-09-27 후속 요청 `우선 배포해줘`로 준비된 신규 매장 지원의 배포를 승인했다. 장비 정보가 없는 실제 저울 연결·수집 활성화는 포함하여 완료했다고 보지 않는다.
- 기존 원본 프로젝트 폴더에서 작업하고 기존 미커밋 변경을 보존한다.
- 이 승인은 신규 매장 추가에 한정한다. 기존 매장 데이터 삭제·재분류, 가격·상품 복제, 기존 계정의 광범위한 권한 변경, 누계 초기화는 포함하지 않는다.
- 저울·라벨프린터의 실제 장비 식별/주소, 계정·상품·가격·행사 장소·기간은 확인된 값만 사용한다. 미확인 값으로 활성화하지 않는다.

CAS의 기존 controller→app 규칙(`2` 접미사 제거)을 보존한다. Linux hostname 제약과 신규 설치기의 식별자 일치 조건을 고려해 영문 ID에 밑줄을 쓰지 않는다. Pi 실제 hostname/SSH 계정은 장비 확인 전까지 미정이다. 이 표는 목표 식별자이며 배포·실연결 완료표가 아니다.

## 담당과 순서

1. **워터비:** 독립 Store 등록, 식별자 연결, 장소·기간 이력, 사업 실적·매출 귀속 기준을 관리한다.
2. **시코드:** 앱 매장 선택, 빈 상품·출력·생산입력 저장공간, 신규 매장 권한, 실시간 동기화, 할인 조회, 저울 연결 매핑을 준비하고 검증한다.
3. **카스씨엘:** 신규 매장 허용목록/변환 경로, 전용 Pi·저울 접속, 중앙 연결, 스냅샷·누계 수집을 준비한다. 연결은 connectivity, 저울 읽기·검증은 scale-data의 경계를 따른다.
4. **실장비 연결:** 확인된 Pi/PC·접속주소·저울 네트워크를 등록한다. 기존 수집기와 중복 실행하지 않고 신규 장비 한 곳만 대상으로 점검한다.
5. **상품·라벨 검증:** 저울 원본을 먼저 읽어 백업한다. 사용자가 확정한 운영상품/가격/코드만 앱과 연결한다. 대상 상품 미확인 상태에서 다른 매장의 상품이나 PLU를 복사하지 않는다.
6. **최종 인수:** 앱의 신규 매장 선택·상품·출력·생산입력, 실제 저울 읽기, 중앙 누계 게시·조회, 워터비 매장 식별, 매출 자료 귀속까지 각각 완료/대기를 기록한다.

## 장소 이동과 실적 보존

- 이력 파일: `instances/store_visits/mooner.yaml`. 실제 장소·시작일을 확인하기 전에는 비워 둔다.
- 새 `StoreVisit`의 `relations.atStore`는 항상 `mooner`이다. 장소가 기존 등록 매장이라면 `hostStore`로 참조할 수 있지만 실적 귀속을 변경하지 않는다.
- `startDate`와 `endDate`는 KST 날짜이며 양끝 날짜를 포함한다. 종료일 미정은 null/생략이다. 이동할 때 이전 방문의 실제 종료일을 기록하고 새 방문을 추가한다. 같은 날 장소가 바뀌면 날짜만으로 분리하지 말고 시간 단위 확장 후 기록한다.
- 운영 기록은 `instances/operations/mooner/YYYY-MM.yaml`을 사용한다. 첫 실제 신고 전에는 가상의 0 생산 장부를 만들지 않는다.
- 팀 이동 때문에 매장 ID를 새로 만들거나 과거 누계·앱 기록을 새 장소로 재귀속하지 않는다. 누계 초기화 여부는 원본에서 검증한다.

## 매출과 중복 방지

- 기존 남선 코드의 `행사팀`은 상품명 키워드 분류다. 새 문어행사팀과 같다는 사용자 확인 또는 원본 식별자 검증 전에는 자동 연결하지 않는다.
- 행사 장소 매출표에 팀 매출이 포함되는지, 팀 별도 자료가 있는지 확인한다. 같은 원본 매출을 매장과 팀 양쪽에서 다시 더하지 않는다.
- 다른 매장의 수수료·가격·상품 구성을 상속하지 않는다. 미확인은 0으로 저장하지 않는다.

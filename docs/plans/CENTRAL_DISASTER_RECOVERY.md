# 중앙 컴퓨터 교체·재해 복구 계약

2026-10-05 사용자 요구: Windows가 완전히 고장 나도 다른 컴퓨터에서 중앙 업무를
복원할 수 있어야 한다. 씽크패드 이전만으로 완료하지 않는다.

## 복원에 필요한 묶음

- 코드: Waterbe/CAS/SeaCode 커밋과 실제 실행 릴리스, 설치 의존성 및 해시.
- 설정: 서비스·타이머·매장 연결·실행 환경·경로 대응표. 특정 Windows 사용자 경로에 의존하지 않는다.
- 상태: SQLite 온라인 백업, 수집 cursor, 동일 작업 ID/dispatch ledger,
  검증된 저울 백업·게시 증거, 미확정 쓰기 및 Telegram outbox/전송 상태.
- 인증: 중앙 Supabase·Telegram 인증과 SSH 키 또는 새 호스트 키 등록 방법.
  Windows DPAPI 파일만 보관해서는 다른 컴퓨터에서 복원할 수 없다.
  복구 가능한 비밀 보관은 Git/대화 밖의 암호화된 별도 보관소를 사용한다.
- 운영: 실행 순서, 상태 점검, 알림 연결, 마지막 백업 시각 및 장애 연락 경로.

## 장애 때 가동 순서

1. 구 중앙의 종료를 확인하거나 접근을 차단한다. 단순 SSH 불통은 종료 증거가 아니다.
2. 새 호스트에 고정 릴리스·의존성·인증·등록된 매장 접근을 복원한다.
3. 백업 해시/SQLite integrity/행수/수집 위치/미확정 작업을 검사한다.
4. 먼저 읽기·수집·보고를 시작한다. 미확정 저울 쓰기는 같은 ID로 증거를
   재조회하며 새로운 요청으로 재전송하지 않는다.
5. 이전 실행 주체가 재개하지 않는 것이 확인되면 변경 워커를 시작한다.
6. 실제 수집·클라우드 ACK·알림 전달과 중복 억제를 확인한다.

## 완료 판정

원본 호스트의 파일/레지스트리/DPAPI 접근 없이 별도 복원 폴더에서 검증해야 한다.
연습 복원은 워커를 자동 시작하지 않으며 물리 저울 변경이나 실제 알림 재발송을
일으키지 않는다. 새 호스트에서 정상 여부를 확인하는 운영 가동은 별도 전환 단계다.

백업은 중앙과 다른 장애 영역에 보관하고 주기/마지막 성공/복원 시험 결과를 기록한다.
최신 백업 이후 미수집 자료 손실 가능성과 목표 복구 시간은 실제 측정하여 보고한다.
임의 컴퓨터가 무인증으로 바로 가동된다는 뜻은 아니다.

활성 중앙 업무는 씽크패드로 이전했고 인증 제외 운영 데이터 자동 백업을 설치했다.
비밀 외부 보관·통합 복원 명령·별도 호스트 복원 시험을 통과하기 전에는
재해 복구 준비 완료로 표시하지 않는다. 호스트 이전과 재해 복구 완료는 다르다.
진행 증거는 [중앙 이전 기록](THINKPAD_CENTRAL_MIGRATION.md)을 따른다.

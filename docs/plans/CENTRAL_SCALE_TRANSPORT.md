# 중앙 저울 통신 / 공유 저장 분리

2026-10-06 합의와 적용 기록. 휴대폰용 공개 HTTPS/도메인/VPN은 만들지 않는다.
시코드↔중앙 요청·결과 교환은 기존 Supabase를 유지한다. 저울 수집 자체는
CASPi→씽크패드 SSH/Tailscale이며 수파를 거치지 않는다. CASPi에는 수파 인증이 없다.

## 책임과 흐름

- 현장: 시코드 Bluetooth → CASPi → 저울. 같은 작업 ID의 검증 영수증 유지.
- 원격: 시코드 → 수파 요청함 → 씽크패드 → CASPi → 저울 → 결과 → 수파 → 앱.
- 자동 누계: 저울 → CASPi 로컬 SQLite → 씽크패드 원본·증가분 저장.
  앱의 공유/조회 결과만 기존 게시 경로로 수파에 보낸다. 초 단위 수파 폴링을 만들지 않는다.
- 시코드는 상품·할인·사용자 편집 원본, CAS는 저울 실행·검증 원본,
  워터비는 출처 연결·사업 해석·공통 이력 담당이다. 누계를 매출로 단정하지 않는다.

## 2026-10-06 실제 적용

- 다섯 CASPi에 단일 서비스 내부 적응형 X1 누계 수집 설치.
  네 고정 매장의 구 cl5200-aggregate-collector.timer는 비활성화했다.
  문어팀은 원래 구 타이머가 없으며 쓰기 비활성을 그대로 보존했다.
- 전체 X1 실측 약4.5~7초. 완료 뒤 최소10초/소요시간3배 중 긴 만큼 쉰다.
  활동 시 전체 주기 약18~30초, 변화 없으면 휴지시간 최대60초다.
  실패 재시도 간격은 최대300초까지 늘린다. 겹쳐 실행하지 않는다.
- 현장/중앙 명령은 공통 foreground intent와 기존 단일 저울 잠금을 사용한다.
  쓰기/재읽기는 중단하지 않는다. 배경 X1은 다음 프레임 경계에서 양보하고
  미완료 회차를 성공으로 저장하지 않는다. 마포 실측 상품 읽기0.348초/BCC 유효.
  실제 휴대폰 쓰기 응답시간 검증과는 다르다.
- 변경 시 전체 검증 스냅샷 저장. 동일 내용은 마지막 성공 확인시각만 갱신하고
  5분마다 완전 스냅샷을 남긴다. KST 날짜 경계에도 새 스냅샷을 보존한다.
  마지막 변경시각과 마지막 실제 확인시각을 구별한다. 기존30일 보존 유지.
- 중앙은 매분 변경 회차를 SSH로 가져와 SQLite에 보존한다. 같은 ID 재수입 억제,
  재조회 겹침은60분에서5분으로 축소. store_observation에 확인시각/실패/오래됨을
  보존한다. 실패 매장만 표시하고 다른 매장 수입은 계속한다.
- 기존 문어팀 영수증 워커는 배경 collect_aggregate/origin=unknown 증거를 중앙
  SQLite에 보존한 뒤 cursor를 전진시킨다. 배경 영수증은 수파에 매회 쓰지 않는다.
  사용자 요청 영수증의 서버 ACK 조건은 유지한다. 다른 매장 전체 영수증 독립
  자동 게시까지 확대 설치한 것은 아니다.
- 문어팀 eth0 DOWN/TimeoutError로 실제 수집 불가. 중앙 실패 표식과 반복
  실패/회복 공통 이력·기존 Telegram 경로 연결. 설치와 물리 정상은 구별한다.

## 부하 완화와 남은 경계

history_worker는 상품5분, 저울 스냅샷·문구·매출원본15분,
출력·진단·영수증60초로 확인하며 마지막 성공10분 겹침 변경분만 조회한다.
첫 baseline/24시간 전체 대조 유지, 날짜 전환만으로 전건 재조회하지 않는다.
~/.local/lib/waterbe-history-low-io-v1에 설치. 생략한 확인시각은 갱신하지 않는다.
실제 수파 I/O 예산 개선량·메일 주원인은 별도 지표 검증 전 단정하지 않는다.

외부 키패드로 바꾼 모든 PLU/문구의 사건 전달·미지원 라벨 설정 감시는 누계와
별개다. 기존 관측을 임의 제거하지 않는다. X1은 관측 구간 누계이며 라벨별 정확한
인쇄시각을 복원하지 못한다. 중앙 공개 API·새 앱 전송기·전체 상품 자동 사건 감시
완성을 주장하지 않는다. 문어팀 랜선/저울 연결과 폰 실제 쓰기는 현장 확인 필요.
